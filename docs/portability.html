🔄 Backend Portability & Cloud Independence
Module 3

ClubLedger follows strict Clean MVVM boundaries: the UI never touches a backend SDK. The entire cloud relay is abstracted behind one Kotlin interface — CloudSyncAdapter — with Firebase Firestore as the shipped default (FirestoreSyncManager). Swapping to Supabase, AWS AppSync, or a self-hosted backend means writing one new implementation of that contract; nothing above the data layer changes. All treasury math runs on-device in pure Kotlin, and the app is 100% functional offline in Room SQLite.

FirestoreSyncManager is the concrete CloudSyncAdapter the ViewModel binds to today. Snapshot listeners stream remote attendances and payments into Room, while every outbound document passes a 64KB Denial-of-Wallet payload guard (isDocumentSafe) and is written under an idempotent compound key so replays never duplicate a record.

Key Architecture Traits
  • ⚡ Sync engine: Firestore snapshot listeners → Room → Compose StateFlow
  • 🔑 Auth: Google / Apple / Facebook via FirebaseAuthManager (CredentialManager)
  • 💾 Local cache: Room SQLite — 12 entities, instant offline UI
  • 🛡️ Guards: isDocumentSafe() 64KB cap + idempotent compound keys per record

// data/remote/FirestoreSyncManager.kt — the default CloudSyncAdapter
class FirestoreSyncManager(
    private val context: Context,
    private val dao: ClubDao,
    private val scope: CoroutineScope
) : CloudSyncAdapter {

    override fun isBackendConfigured(): Boolean = /* FirebaseApp ready? */

    override suspend fun pushAttendanceToCloud(a: Attendance) {
        val db = firestore ?: return
        if (!isDocumentSafe(a)) return  // 64KB payload guard
        val docId = SecurityDefenseHelper.createIdempotentAttendanceKey(
            userId = a.userId, teamId = a.teamId,
            sessionDate = a.sessionDate, sessionType = a.sessionType
        )
        db.collection("clubs").document(activeClubId)
            .collection("attendances").document(docId)
            .set(a).await()
    }
}

1. The CloudSyncAdapter Contract

The ViewModel and screens talk to ClubViewModel's CloudSyncAdapter-typed field only. No Firebase import leaks above the data layer — the shipped manager is one interchangeable implementation:

interface CloudSyncAdapter {
    val syncState: StateFlow<CloudSyncState>
    fun isBackendConfigured(): Boolean
    fun enableCloudSync(clubId: String)
    fun disableCloudSync()
    suspend fun pushAllLocalToCloud()
    suspend fun pushAttendanceToCloud(attendance: Attendance)
    suspend fun pushPaymentToCloud(payment: Payment)
    suspend fun pushLedgerEntryToCloud(entry: BalanceLedger)
}
💾

2. Vendor-Neutral Room — 12 Entities

All twelve entities (User, Team, TeamMembership, Attendance, Payment, TeamBudget, Invoice, InvoiceAllocation, BalanceLedger, AuditLog, Dispute, TeamJoinRequest) live in local Room SQLite. Shares, percentages, cent rounding, ledger balances, and dispute credits are computed on-device — zero network required for the app to be fully usable pitch-side.

✓ Zero cloud locks: even cloud sync itself is feature-detected — without google-services.json the app runs happily in Local Mode.
🔗

3. Share API & 1-Click Exports

Team invites travel as clubledger://join?code=TEAM-1234 deep links — registered in AndroidManifest.xml, parsed in MainActivity on cold start, and prefilled straight into the Join Team dialog over WhatsApp, SMS, Slack, or email.

✓ 1-click CSV exports: generateAttendanceCsv() and generatePaymentsCsv() (plus the ledger export) produce spreadsheet-ready files for Excel, Google Sheets, or QuickBooks — no backend involved.
