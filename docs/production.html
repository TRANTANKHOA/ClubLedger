🚀 Production Engineering & CI/CD Pipeline
Module 5

This page is the condensed web runbook. The canonical, step-by-step guide lives in the repository: DEPLOYMENT.md.

1. Local Development Environment

🛠️

Prerequisites

JDK 17 (Homebrew: brew install openjdk@17), Android SDK API 34+, Android Studio Iguana+. macOS one-command setup: ./scripts/setup_mac.sh.

🧪

Test & Build Loop

./scripts/run_tests.sh (45 unit tests), ./scripts/build_apk.sh (debug APK), ./scripts/run_app.sh (install & launch on a device).

2. Firebase & Cloud Multi-User Setup (Optional)

ClubLedger runs Offline-First on Room SQLite by default. To enable live multi-device sync and social sign-in:

StepAction
1Create a Firebase project at console.firebase.google.com
2Register an Android app — package name com.aistudio.clubledger.sports (must match applicationId in app/build.gradle.kts)
3Add the SHA-1 fingerprint (obtain via ./gradlew signingReport)
4Enable Authentication sign-ins: Google, Apple (Team ID + Service ID), Facebook (App ID + Secret)
5Enable Cloud Firestore (production mode rules)
6Download google-services.json into app/ and rebuild

3. Firestore Security Rules

Baseline rules (firestore.rules) protect the clubs/{clubId} tree: authenticated reads, type-validated writes, deletes blocked on immutable collections. Deploy with:

Deploy rules
firebase login
./scripts/deploy-firestore-rules.sh
Cloud sync assumes a signed-in user — unauthenticated pushes are denied by design. Tighten role-based writes before real multi-tenant use.

4. Release Keystore & Signing

Generate + configure the release keystore
./scripts/generate_release_keystore.sh

# then export before release builds (alias: clubledger)
export KEYSTORE_PATH=/absolute/path/release.keystore
export STORE_PASSWORD='<your-keystore-password>'
export KEY_PASSWORD='<your-key-password>'
export RELEASE_KEY_ALIAS=clubledger # defaults to 'upload' if unset
The signing config reads environment variables — gradle.properties has no effect. Never commit keystores or passwords.

6. GitHub Actions CI/CD Pipeline

Every push/PR to main runs tests and assembles a debug APK; merges to main also build an app bundle (signed only when keystore secrets are configured — otherwise unsigned).

name: ClubLedger CI/CD Pipeline on: push: branches: [ main, 'release/*' ] pull_request: branches: [ main ] jobs: build_and_test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-java@v4 with: { distribution: 'temurin', java-version: '17', cache: 'gradle' } - name: Make scripts executable run: chmod +x gradlew scripts/*.sh || true - name: Generate debug keystore # custom debugConfig expects <root>/debug.keystore run: keytool -genkeypair -v -keystore debug.keystore -alias androiddebugkey -storepass android -keypass android -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Android Debug,O=Android,C=US" - name: Run Unit & JVM Tests run: ./gradlew testDebugUnitTest --continue - name: Build Debug APK run: ./gradlew assembleDebug release_bundle: needs: build_and_test if: github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/heads/release/') steps: - uses: actions/checkout@v4 - uses: actions/setup-java@v4 with: { distribution: 'temurin', java-version: '17', cache: 'gradle' } - name: Make scripts executable run: chmod +x gradlew scripts/*.sh || true - name: Decode Keystore (if secret provided) env: { KEYSTORE_BASE64: "${{ secrets.RELEASE_KEYSTORE_BASE64 }}" } run: echo "$KEYSTORE_BASE64" | base64 -d > release.keystore - name: Build Production Android App Bundle (AAB) run: ./gradlew :app:bundleRelease
