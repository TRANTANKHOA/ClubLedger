The Transparent Fair-Share Equation
Member Share = (Attended Sessions / Total Team Sessions) × Monthly Budget
Attended 0 sessions? You pay $0.00. Attended 8 out of 30 sessions on a $1,500 budget? You owe exactly $400.00 (26.7%).

Auto-Recalculate Engine

End-to-End System Architecture & Data Flow

How touch events cascade from Jetpack Compose UI down to Room Persistence and back via reactive Flow streams.

Tier 01

1. Presentation Layer (Jetpack Compose Frontend)

User interacts with interactive Composables (e.g. Member submits payment, Admin approves attendance, or triggers cost re-allocation). State is observed via collectAsState().

Jetpack Compose • M3 UI
↓ User Action / Intent Call
Tier 02

2. Controller & State Layer (ClubViewModel)

ClubViewModel receives the user intent, validates input constraints, sanitizes data payloads, and launches coroutines inside viewModelScope(Dispatchers.IO).

ViewModel • Coroutines • StateFlow
↓ Domain Operation & Calculation
Tier 03

3. Business Logic & Calculation Engines (Backend Logic)

Executes domain mathematical models: Proportional Cost Allocation Engine, Double-Entry Running Balance Calculator, and generates tamper-evident Audit Trail Logs.

Cost Engine • Math Logic
↓ Transaction & SQL Queries
Tier 04

4. Persistence & Database Layer (Room SQLite)

ClubDao executes atomic @Transaction operations against SQLite tables with foreign key constraints, indexes, and write-ahead logging.

Room DB • SQLite DAO
⟳ Reactive Flow Observer Loop
Loop ⟳

5. Reactive Emission & Instant Recomposition

Room automatically emits new data over Flow<List<T>>. The UI observes changes and recomposes instantly with 0ms manual polling.

Reactive Flow • 0ms Polling
